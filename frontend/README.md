# WireMap — фронтенд (React)

React + TypeScript + Vite поверх API из `backend/`. Пришёл на замену пробному
прототипу на чистом JS без сборки — тот был одноразовым, для нащупывания
модели данных, и удалён из дерева (история осталась в git).

## Стек

- **Vite + React 19 + TypeScript** — сборка и сам фреймворк.
- **React Router** — роутинг (`/devices`, `/templates`, `/links`, `/topology`, ...).
- **TanStack Query** — серверное состояние: кеш, инвалидация после мутаций,
  `isPending`/`isLoading` без ручного стейта.
- **Mantine** (`@mantine/core`, `@mantine/hooks`, `@mantine/notifications`) —
  компоненты интерфейса: таблицы, модалки, `Select`/`MultiSelect`,
  `ColorInput`, тосты. Почти всё, что раньше собиралось руками на чистом
  JS (модалка, дерево тегов, пикер цвета), здесь готовые компоненты.
- **@joint/core (JointJS)** — схема связей (`src/pages/TopologyPage.tsx`).
  Разводка и начертание линии — две отдельные настройки вида
  (`edgeRouter` и `edgeConnector` в `topology/appearance.ts`), обе живут в
  `localStorage`. Роутер: прямая (`normal`), обход чужих карточек прямыми
  углами (`manhattan`), он же с диагоналями (`metro`) или углы без обхода
  (`rightAngle`); у обходящих соседние кабели разводятся разными коридорами,
  иначе они сливаются в одну линию. Коннектор: острые углы, скругление
  (`rounded`), дуга (`curve`) или «мостик» на пересечении (`jumpover`).
  Скругление на прямой разводке ничего не даёт — у отрезка из двух точек
  нет углов; кривизну там даёт только дуга.

  Привязка к сетке (`topology/grid.ts`) ровняет **середину** карточки, а не
  её угол: кабель цепляется к середине (`anchor: { name: 'center' }`), и
  прямым он идёт ровно тогда, когда середины совпадают. У карточек разной
  ширины при этом не совпадают края — размен сознательный, на схеме связей
  читают кабели. Рамки групп — наоборот, по контуру (`snapBoxOut`, округление
  размера в `joint/tools.ts`): кабели к ним не цепляются.

  Встроенная привязка полотна выключена (`gridSize: 1`) — она ровняет угол.
  Вместо неё перетаскивание округляет свой вид ячейки: `elementView` со своим
  `snapToGrid` (`joint/useJointPaper.ts`) — штатная точка расширения
  JointJS, вызываемая из `ElementView.drag`. Мимо полотна идут и округляются
  в `grid.ts` растяжка рамки, обе автоматические раскладки
  (`topology/layout.ts`) и первичная расстановка пружинной моделью
  (`joint/buildGraph.ts`). Шаг рисунка сетки задан отдельным `drawGridSize`:
  одним числом на двоих выключенная привязка превратила бы сетку в заливку из
  линий через пиксель. Позиции, сохранённые человеком, при открытии схемы не
  пересчитываются — переставлять чужую работу молча нельзя.

  Узлы, рамки групп и заглушка повисшего конца — свои фигуры
  (`src/pages/topology/joint/shapes.ts`), панели действий на узле и на
  рамке — свои инструменты (`joint/tools.ts`). Группа держит своё
  содержимое: узел не выходит за рамку, а состав меняется только явно.
  Начальная раскладка — пружинная модель (`src/pages/topology/layout.ts`):
  устройства без сохранённой позиции сами раскладываются по связям, а
  перетащенное руками «замораживается» — позиция хранится на бэкенде
  (`PATCH /devices/{id}/position`), а не только в браузере.
  Схема была и на React Flow; вариант удалён после выбора в пользу
  JointJS — прежде всего ради ортогональной разводки.
  На том же полотне рисуется «Структура БД» (`src/pages/SchemaPage.tsx`):
  таблицы живой базы и стрелки внешних ключей от колонки к колонке,
  автоматическая раскладка по слоям. Схема была на React Flow; после
  переезда библиотека из зависимостей ушла.

## Запуск

```bash
npm install
npm run dev
```

Откроется на `http://localhost:5173`. Бэкенд должен быть поднят отдельно
(`cd ../backend && docker compose up -d --build`) — адрес API задаётся на
экране входа (по умолчанию `http://localhost:8000`, сохраняется в
localStorage).

```bash
npm run build   # tsc -b && vite build — прод-сборка в dist/
```

## Структура

```
src/
  api/
    schema.ts        — генерируется из openapi.json, руками не правится
    types.ts         — псевдонимы над schema.ts + параметры строки запроса
    client.ts        — тонкий fetch-клиент (токен, базовый URL, ошибки)
    endpoints.ts     — по функции на каждый эндпоинт
    hooks.ts         — useQuery/useMutation-обёртки с инвалидацией кеша
  auth/              — контекст авторизации, экран входа, RequireAuth/RequireAdmin
  layout/            — AppShell с боковой навигацией
  lib/               — утилиты (nn/nnInt — пустая строка формы -> null, дерево тегов, тосты)
  pages/             — по странице на раздел; у Устройств и Топологии — свои подпапки
    devices/         — карточка устройства, форма (шаблон + теги + группа на топологии), строка порта
    topology/         — схема связей на JointJS: joint/shapes.ts (узел-карточка),
                         joint/tools.ts (панель действий), layout.ts (пружинная
                         раскладка), TopologyGroupsModal
    schema/           — структура БД на том же полотне: joint/tableShape.ts
```

## Заметки

- Группа на топологии (`topology_group_id`) — отдельный от тегов параметр:
  ровно одна группа на устройство, только для визуальной кластеризации на
  схеме связей (пунктирная рамка). Теги многозначны и вложены, для рамки
  контейнера нужен один-единственный родитель — поэтому это не то же самое
  поле и управляется отдельной кнопкой «Группы» на странице топологии, а не
  через список тегов.
- Типы тел запросов и ответов генерируются из описания API. Порядок такой:
  меняется `backend/app/schemas.py` → `cd ../backend && python -m
  scripts.dump_openapi` обновляет `backend/openapi.json` → `npm run codegen`
  пересобирает `src/api/schema.ts`. Оба файла лежат в репозитории и
  проверяются в CI, так что расхождение падает сборкой, а не всплывает на
  работающем интерфейсе. Править `schema.ts` руками бессмысленно — следующий
  `codegen` затрёт.
- `npm audit` показывает уязвимость в `react-router` (CSRF в RSC-режиме) —
  не относится к нам: приложение не использует RSC, роутинг чисто
  клиентский (`BrowserRouter`). Даунгрейдить не стал, чтобы не откатывать
  версию без необходимости; стоит последить за апдейтом `react-router-dom`.
