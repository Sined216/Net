# WireMap Обход — приложение для сверки на месте

Android-приложение к WireMap: унести спецификацию площадки в цех, где нет
сети, сверить её с тем, что стоит в шкафах, отметить найденное — и
выгрузить обратно, вернувшись в офис.

**Найденное не попадает в спецификацию напрямую.** Оно ложится в
промежуточные таблицы WireMap, откуда человек переносит записи по одной,
глядя на то, что уже заведено. Так решил заказчик, и это снимает главную
сложность оффлайновой работы: снимок в руках устаревает за смену, и
писать поверх чужих правок вслепую нельзя.

## Как этим пользуются

1. **В офисе.** Открыть приложение, вписать адрес WireMap и войти. Нажать
   «Забрать снимок» — на телефон приедут устройства с портами, связи и
   справочники.
2. **В цеху, без сети.** Смотреть спецификацию, искать устройства,
   открывать карточку с портами. У каждого гнезда видно, занято ли оно
   *по документации* и чем именно — это и есть предмет сверки. Что
   нашлось лишнего: «+ Устройство» и «+ Связь», либо кнопка «Есть кабель»
   прямо у свободного гнезда.
3. **Обратно в офисе.** «Выгрузить найденное». Дальше — в WireMap, на
   странице «Импорт и обход»: там записи разбирают и переносят.

Повторная выгрузка безопасна: у каждой записи есть ключ, выданный
телефоном ещё оффлайн, и сервер не заведёт её дважды. Если связь
оборвалась и непонятно, дошло ли, — просто нажмите ещё раз.

## Разработка

```bash
cd mobile
npm install
npm start          # Metro; открыть в Expo Go на телефоне
npm run typecheck  # проверка типов
npm run bundle     # собрать бандл — ловит ошибки импортов и сборки
npm run codegen    # перегенерировать типы после правок API бэкенда
```

Типы обмена (`src/api/schema.ts`) генерируются из `backend/openapi.json` —
тем же способом, что и у сайта. Руками их не правят: разъедется телефон с
сервером — узнается это в цеху, где чинить нечем.

## Сборка APK

Приложение ставится файлом, без Google Play:

```bash
npx eas build --platform android --profile preview
```

### Что нужно настроить один раз

Два значения знает только владелец аккаунта Expo, и в репозитории их нет:

1. **Идентификатор проекта.** Выполните в папке `mobile`:
   ```bash
   npx eas init
   ```
   Команда создаст проект в вашем аккаунте и допишет в `app.json`
   `extra.eas.projectId` и `owner`. Этот коммит нужно сохранить в
   репозиторий, иначе сборка из GitHub не будет знать, куда собирать.

2. **Корневая папка сборки.** В репозитории несколько частей
   (`backend/`, `frontend/`, `mobile/`), а приложение живёт в `mobile/`.
   На expo.dev в настройках проекта → GitHub укажите **base directory**:
   `mobile`. Без этого EAS будет искать `package.json` в корне и не
   найдёт приложения.

### Почему разрешён незашифрованный HTTP

В `app.json` включён `usesCleartextTraffic`. WireMap в заводской сети
обычно работает по `http://`, а Android с девятой версии такие запросы
по умолчанию запрещает — без этой настройки собранное приложение просто
не достучалось бы до сервера, причём в `npm start` через Expo Go всё
работало бы, и разошлось бы только на собранном APK.

Если WireMap у вас за HTTPS, настройку лучше убрать.

## Чего в приложении нет

- **Правки существующих устройств и связей.** В цеху спецификацию
  сверяют и дополняют, а не переписывают: правка требует разбора
  расхождений, которого сознательно решили избежать.
- **Сканера штрихкодов.** Задуман, но не сделан — стоит добавить, если
  на оборудовании есть наклейки с кодом: искать устройство в списке из
  тысячи руками долго.
- **Фотографий.** Вложений нет и на стороне сервера (пункт 2.8 ТЗ).
