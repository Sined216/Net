Поиск не находит того, что ищут чаще всего

провереноrouters/interfaces.py:209

Страница называется «Поиск по IP / MAC / имени». Запрос строится INNER JOIN'ом от interfaces к devices и смотрит только на поля порта — Device.management_ip и Device.mac в поиске не участвуют вовсе, хотя в списке устройств по ним есть и колонки, и фильтры. 

поиск «10.10.10.20» — IP управления SW-0001 → 0 результатов
   (а список устройств по этому же адресу находит SW-0001)
поиск «a4:bb:6d:00:00:00» — MAC устройства  → 0 результатов
поиск «CAM-0001» — устройство без портов    → 0 результатов
поиск «SW-0001» — один коммутатор           → 24 строки, по одной на порт

Устройство с нулём портов (медиаконвертер, ИБП) невидимо целиком — ни по коду, ни по имени. Коммутатор, наоборот, забивает выдачу: при жёстком лимите в 50 две железки съедают весь ответ.

ЛечитсяLEFT OUTER вместо INNER, добавлением полей устройства в условие и схлопыванием результата до устройства

4

База не может гарантировать «один кабель на порт»

провереноmodels.py · routers/links.py:12

У links есть UNIQUE(interface_a_id) и UNIQUE(interface_b_id) по отдельности плюс CHECK (a < b). Этого не хватает: порт может быть стороной A в одной связи и стороной B в другой. Прямой INSERT в базу, поднятую миграциями: 

link (20,30) inserted
>>> DB ACCEPTED (10,20): port 20 is now in two links
links now: [(1, 20, 30), (2, 10, 20)]
links touching port 20 = 2

Комментарий в models.py утверждает, что «база теперь это гарантирует», — она гарантирует лишь отсутствие зеркального дубля той же пары. Единственная настоящая проверка — _busy(), а это check-then-act без замка: два одновременных запроса пройдут оба.

Последствие тихое: build_link_map кладёт связи в словарь по interface_id, поэтому у порта с двумя кабелями останется видимым только последний — второй пропадает из интерфейса, продолжая существовать в базе.

ЛечитсяОтдельной таблицей концов с одним UNIQUE(interface_id) либо SELECT … FOR UPDATE перед вставкой

Обязательная смена пароля действует только в браузере

провереноauth.py · AppLayout.tsx

must_change_password проверяет исключительно AppLayout, показывая модалку без крестика. get_current_user этот флаг не смотрит вовсе — значит токен, выданный по временному паролю, полноценен:

Человек, которому администратор продиктовал временный пароль, может годами работать через API и Swagger, ни разу его не сменив. Это же касается BOOTSTRAP_ADMIN_PASSWORD: README обещает, что «интерфейс потребует сменить его при первом входе», — API не потребует.

Оптимистичная блокировка обходится устаревшей формой

devices/InterfaceRow.tsx:27-60

Поля инициализируются через useState(iface.ip ?? '') — один раз при монтировании. Номер правки при этом читается из живого пропа в момент сохранения: version: iface.version. Пара «значения — версия» разъезжается: 

1. A открыл страницу: порт 5, ip 10.0.0.5, version 1
2. B поменял тот же порт на 10.0.0.99          → version 2
3. A сохранил ДРУГОЙ порт того же устройства   → рефетч
   у строки 5 проп стал version 2 и ip 10.0.0.99,
   но поля ввода по-прежнему показывают 10.0.0.5
4. A жмёт «сохранить» на строке 5:
   уходит version: 2 (свежий) + ip: 10.0.0.5 (устаревший)
   → версии совпали → правка B молча затёрта

Ровно тот сценарий, ради которого блокировку и вводили.

ЛечитсяЗахватом версии вместе со снимком полей — одним useState({...iface})

Импорт: файл целиком в память до проверки размера

routers/imports.py:33
content = await file.read()      # читается ВЕСЬ файл
if len(content) > MAX_BYTES:     # и только потом проверяется

Лимит в 16 МБ отсекает файл уже после того, как он занял память. Вдобавок importer.parse() — синхронный разбор внутри async def: на время обработки десятитысячной таблицы блокируется весь event loop. Права нужны редакторские, так что это не дыра, а запас прочности.

ЛечитсяЧтением потоком с обрывом на лимите и выносом разбора в run_in_threadpool
12

Развёртывание: лишняя мишень и открытый канал

docker-compose.yml · nginx.conf · config.py

docker-compose.yml публикует бэкенд наружу ("${API_PORT:-8000}:8000") — по умолчанию на всех интерфейсах, вместе со Swagger UI. Интерфейсу этот порт не нужен, он ходит через nginx. Базу авторы закрыли ровно по этой логике.

В nginx.conf нет ни одного security-заголовка. HTTPS не предусмотрен нигде, а README прямо зовёт открывать систему по http://<ip>:8080 с других машин — токен и пароль идут по сети открытым текстом.

bootstrap_admin_password — единственная настройка, которую проверка продовой конфигурации не смотрит: дефолт change-me-please пройдёт молча. В compose переменная обязательна, так что этот путь закрыт, — но проверка рядом с SECRET_KEY всё равно напрашивается.

Чего в продукте нет как класса не ошибки — направления

Незакрытые направления, заметные именно для документирования заводской сети.

Экспорт

Ни спецификации в XLSX, ни кабельного журнала, ни схемы в PNG/SVG/PDF. Для передачи подрядчику или в архив это обычно первое, что спрашивают.

Пассивная инфраструктура

Связь строго «порт ↔ порт». Патч-панелей, кроссов, розеток нет — линия «коммутатор → патч-панель → розетка → станок» документируется только сквозным упрощением.

Стойки и юниты

Вид группы «шкаф» на схеме есть, но юнитов и позиции в стойке нет.

IPAM

VLAN есть, подсетей, пулов и проверки конфликтов IP нет.

Вложения

Фото шкафа, паспорт устройства, скан схемы приложить некуда.

Опрос SNMP / LLDP

Поля source, confirmed, last_seen_at, speed_mbps заведены под него и пока лежат мёртвым весом.
