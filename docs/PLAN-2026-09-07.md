# WireMap — план доработок топологии

Дата: 2026-09-07. Ветка: `claude/repo-review-and-spec-t2k8mf`, ревизия `dee638b`.

План собран после того, как тестовая копия схемы без групп (`/topology-test`,
ревизия `8ae0c4f`) прожила рядом с обычной достаточно, чтобы сравнить. Вывод
владельца: **без рамок лучше**. Отсюда четыре решения, которые этот план и
расписывает:

1. Старая топология с рамками убирается целиком — остаётся одна схема.
2. Рамки групп вычищаются из кода схемы полностью, а не прячутся настройкой.
3. Сбоку от полотна появляется панель с деревом; деревьев несколько видов.
4. Выбор ветки в дереве подсвечивает на схеме то, что к ней относится,
   а всё прочее приглушает.

Группы при этом никуда не деваются как данные: они перестают быть рамкой на
полотне и становятся одним из деревьев в панели, а заводят и правят их на
отдельной странице — как теги и VLAN.

## Заход 4. VLAN в ответе схемы

Единственная из пяти веток, которой не хватает данных. VLAN живут на портах:
`interfaces.vlan_id` — access, `interface_trunk_vlans` — транк.

- `schemas.py`: добавить `vlan_ids: list[int]` в `TopologyNode` и в
  `TopologyEdge`.
- `routers/topology.py`: два запроса без N+1 — access-VLAN по портам,
  сгруппированные по устройству и по порту, и транк-VLAN тем же способом.
  У узла — объединение по всем его портам, у кабеля — объединение по двум
  его портам. Ответ растёт на пару чисел на объект; сегодняшний принцип
  «три запроса, ни один не растёт от числа портов» сохраняется — станет
  пять.
- `python -m scripts.dump_openapi` → `npm run codegen`: оба файла лежат
  в репозитории и проверяются CI, иначе сборка упадёт.
- Тесты на бэкенде: устройство с access-VLAN, устройство с транком, кабель
  между ними — проверить, что `vlan_ids` совпадает с ожидаемым множеством.

**Почему в `/topology`, а не отдельной ручкой.** Схема и так грузится одним
запросом, а VLAN нужен ровно в тот же момент, что и всё остальное. Отдельная
ручка — это второй круг ожидания ради полей на несколько байт.

## Заход 6. Подсветка и приглушение

Решение по поведению: **выбранное обводится и остаётся ярким, всё прочее
гаснет до полупрозрачного, но остаётся на месте** — видно и выбранное, и
где оно стоит относительно всей сети.

Что считается «относящимся к ветке»:

| Выбрано | Подсвечиваются устройства | Подсвечиваются кабели |
|---|---|---|
| Группа / тег / тип / модель | все под веткой, включая вложенные | те, у которых **хотя бы один** конец внутри — так видно и внутренние связи, и выходы наружу |
| Отдельное устройство | оно само | все его кабели |
| VLAN | у кого есть порт в этом VLAN | те, чей порт с обеих или с одной стороны в этом VLAN |

**Как это делается технически — важно.** Не через правку атрибутов модели:
у линии смена атрибутов заставляет JointJS пересчитать маршрут, а это на
тысяче кабелей ощутимо. Вместо этого — класс на **виде** ячейки и один
класс на полотне: `.joint-paper.dimmed .joint-cell:not(.picked)` гасится
прозрачностью через CSS. Переключение класса не трогает модель и не
перезапускает обходчик.

- Новый `joint/highlight.ts`: `applyHighlight(paper, { devices: Set, links: Set })`
  — снимает прежние классы и расставляет новые.
- Вызывать его надо там же, где сейчас зовётся `refreshTools()`: граф
  пересобирается на каждое изменение данных, ячейки создаются заново, и
  подсветку, как и панель действий, приходится ставить снова.
- Обратная связь (необязательно, но дёшево): щелчок по карточке на схеме
  раскрывает и подсвечивает её ветку в дереве — иначе панель и полотно
  живут двумя несвязанными списками.

## Проверка

Каждый заход проверяется живьём на площадке с группами (три шкафа,
«Проверка разводки»), а не только сборкой:

```bash
cd frontend && npx tsc -b --noEmit && npm run lint && npm run build
cd ../backend && python -m pytest          # заход 4
```

1. **После захода 1–2**: на `/topology` нет ни одной рамки; устройство с
   `topology_group_id` таскается куда угодно; «Разложить» кладёт всё общим
   рядом; в `pages/topology/` нет вхождений «group» (`grep -ri group`);
   старые ключи вида про рамки исчезают из `localStorage` при первом
   чтении настроек.
2. **После захода 3**: группу можно завести, переименовать, удалить и
   набрать в неё устройства со страницы «Группы»; на схеме от этого ничего
   не меняется.
3. **После захода 4**: `GET /topology` отдаёт `vlan_ids` у узлов и кабелей;
   значения сверены с базой на устройстве с access-VLAN и с транком.
4. **После захода 5–6**: выбор ветки каждого из пяти деревьев подсвечивает
   ожидаемое множество — проверять **счётом подсвеченных ячеек в DOM**, а
   не глазами: `document.querySelectorAll('.joint-cell.picked').length`
   должно совпадать с числом, посчитанным по данным. Отдельно — что при
   1000 устройств переключение веток не роняет отзывчивость (замерить
   время между щелчком и перерисовкой) и что маршруты кабелей при
   подсветке **не пересчитываются** (отпечаток `d` у путей до и после
   выбора должен совпасть побайтово).
